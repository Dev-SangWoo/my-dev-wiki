# Store Knowledge Workflow

새로운 개발 지식을 저장하거나 기존 이해를 갱신할 때 사용한다.

항상 루트 `AGENTS.md`의 Core Rules를 우선한다.

## Procedure

1. **현재 이해 확인**
   - 사용자가 실제로 이해해서 자신의 언어로 표현한 부분을 찾는다.
   - 단순히 제공된 자료, LLM의 설명, 복사된 원문은 사용자 이해로 취급하지 않는다.
   - 명백한 사실 오류가 있으면 저장 전에 대화에서 교정한다.

2. **의미 단위 분석**
   - 입력 하나를 파일 하나로 가정하지 않는다.
   - 긴 입력에 여러 독립적인 이해가 있으면 의미 단위 후보로 나눈다.
   - 여러 개념 사이의 관계 자체가 중요한 mental model이면 synthesis 지식 후보로 본다.
   - 단순 키워드 언급만으로 파일을 만들지 않는다.

3. **기존 지식 검색**
   - `INDEX.md`에서 관련 domain을 확인한다.
   - 파일명과 본문을 검색해 기존 관련 지식을 찾는다.
   - 새 파일 생성보다 기존 파일 병합을 우선한다.

4. **병합 또는 생성 결정**
   - 기존 파일과 같은 생각 단위라면 해당 파일을 갱신한다.
   - 나중에 독립적으로 회상할 가치가 있고 충분한 이해가 형성되었을 때만 새 파일을 만든다.
   - 과도하게 atomize하지 않는다.

5. **Current Understanding 작성**
   - 사용자의 표현을 보존한다.
   - 허용: 오탈자, 줄바꿈, 최소한의 정돈, 의미 없는 중복 제거.
   - 금지: 전문적인 정의로 재작성, 사용자가 말하지 않은 설명 추가, LLM의 설명을 사용자 이해처럼 삽입.
   - 기존 이해가 의미 있게 바뀌었다면 현재 이해는 최신 상태로 갱신한다.

6. **Open Questions 갱신**
   - 사용자가 아직 이해하지 못했거나 명확히 설명하지 못하는 질문을 남긴다.
   - 해결된 질문은 제거한다.

7. **Understanding Timeline 갱신**
   - 중요한 오해 교정, mental model 변화, 새로운 관계 이해 등 의미 있는 사고 변화만 기록한다.
   - 오탈자, 링크 추가, 파일 이동 같은 변경은 기록하지 않는다.

8. **Connections 갱신**
   - 실제로 존재하는 관련 지식 파일만 연결한다.
   - 단순 태그 목록이 아니라 함께 회상할 가치가 있는 의미 있는 관계만 둔다.
   - 가능하면 관계 이유를 짧게 적는다.
   - 새 연결이 기존 문서에도 유용하면 반대쪽 Connections도 갱신한다.

9. **Sources 갱신**
   - 책, 공식 문서, 강의, 프로젝트 경험 등 사용자가 제공한 학습 맥락을 기록한다.
   - 출처를 추측해서 만들지 않는다.

10. **개념 누락 검증**
    - 사용자가 학습 자료와 함께 자신의 요약을 제공했거나, 대화에서 만든 요약을 명시적으로 저장하도록 승인했다면 저장 전에 의미 있는 개념 체크리스트를 만든다.
    - 체크리스트에서는 단순 예제 코드보다 `정의`, `개념 간 구분`, `판단 기준`, `주의점`, `문제 해결 흐름`, `의미 있는 연결`을 우선한다.
    - 저장 또는 갱신 후 변경된 지식 파일을 다시 읽고, 사용자가 직접 표현했거나 명시적으로 승인한 개념이 빠지지 않았는지 체크리스트와 대조한다.
    - 같은 개념이 이미 다른 지식 파일에 충분히 저장되어 있다면 중복해서 복사하지 않고 의미 있는 `Connections`로 연결할 수 있다.
    - 학습 자료에만 있고 사용자가 아직 이해했다고 표현하거나 승인하지 않은 개념은 `Current Understanding`에 자동으로 넣지 않는다. 중요한 누락 후보라면 현재 대화에서 별도로 알려 확인할 수 있게 한다.

11. **INDEX 갱신**
    - 새 주요 지식 파일이 생기거나 경로가 바뀐 경우에만 `INDEX.md`를 갱신한다.

## Result

한 번의 입력은 0개, 1개 또는 여러 파일 변경으로 이어질 수 있다. 새로운 이해가 없다면 아무것도 저장하지 않아도 된다.
