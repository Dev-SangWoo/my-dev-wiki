# JavaScript 기본형·참조형과 복사

## Current Understanding

1. 기본형은 값을 다른 변수에 넣으면 값이 복사되어 이후에는 서로 독립적으로 움직인다고 이해한다.

```js
let a = 10;
let b = a;
a = 20;

// b는 10
```

2. 객체에서는 `obj2 = obj1`처럼 대입하면 객체 자체를 하나 더 만드는 게 아니라 같은 객체를 바라보게 된다고 이해한다. 처음에는 "obj2는 저 객체의 주소만 가져온다"고 표현했고, 정확하게는 **객체를 가리키는 참조값이 복사된다**고 정리했다. 그래서 한쪽에서 같은 객체의 내부 값을 바꾸면 다른 변수에서도 바뀐 값이 보인다.

```js
const obj1 = { name: "상우" };
const obj2 = obj1;

obj1.name = "철수";
// obj2.name도 "철수"
```

3. 스프레드 연산자는 "한 단계만 벗겨서 사용하는 얕은 복사"로 이해한다. `{ ...obj }`를 하면 바깥 객체는 새로 생기지만, 안쪽에 또 객체가 있으면 그 중첩 객체의 참조는 그대로 공유될 수 있다.

```js
const original = {
  user: {
    name: "상우"
  }
};

const copy = { ...original };

original === copy;           // false
original.user === copy.user; // true
```

4. 중첩된 `user`도 따로 스프레드하면 그 단계의 참조까지 분리된다고 이해한다.

```js
const copy = {
  ...original,
  user: {
    ...original.user
  }
};

original.user === copy.user; // false
```

다만 더 안쪽에 `profile` 같은 객체가 또 있다면, `user`까지만 복사한 것으로는 `profile`까지 자동으로 분리되는 것은 아니다.

5. 깊은 복사는 "안까지 복사한다"고 이해한다. 중첩된 객체들까지 새로 만들어 원본과 독립시키는 복사다. `structuredClone()` 같은 방법을 사용할 수 있다.

6. `const`로 선언한 객체나 배열도 내부 값은 바꿀 수 있다고 이해한다. `arr.push(4)`가 가능한 이유는 "객체 자체를 바꾸는 게 아니기 때문"이다. `const`는 변수가 다른 객체를 다시 가리키도록 재할당하는 것을 막지만, 가리키고 있는 객체 내부의 변경까지 자동으로 막지는 않는다.

7. React의 객체 state와도 참조 개념이 연결된다고 이해했다. `user.profile.name`만 직접 바꾸고 같은 `user` 객체를 `setUser(user)`로 다시 넘기면 바깥 객체의 참조가 그대로라 같은 state로 판단되어 업데이트를 건너뛸 수 있다. 그래서 변경되는 경로의 객체를 새로 만들어 `setState`에 넘기는 방식이 필요하다.

처음에는 React가 "얕은 복사로 비교해서 찾는다"고 생각했지만, `useState`의 state 갱신에서는 이전 state와 새 state를 `Object.is`로 비교하고, 객체라면 같은 참조인지가 중요하다는 쪽으로 교정했다.

## Quick Recall

```text
기본형 복사
→ 값이 복사됨
→ 이후 서로 독립

객체 대입
→ 객체를 가리키는 참조값이 복사됨
→ 같은 객체를 함께 볼 수 있음

spread
→ 펼친 객체 한 단계만 새로 만듦
→ 중첩 객체는 참조를 공유할 수 있음

중첩 spread
→ 펼친 단계까지 참조 분리

깊은 복사
→ 중첩 객체까지 독립적으로 복사

const + 객체
→ 재할당은 불가
→ 객체 내부 변경은 가능
```

## Open Questions

- 변수(Variable)와 식별자(Identifier)의 차이는 요약본에 있지만 아직 내 말로 다시 설명해 보지는 않았다.
- 함수가 일급 객체라는 의미와 콜백/클로저로 이어지는 관계는 아직 이번 복습에서 확인하지 않았다.
- `undefined`와 `null`의 차이 및 PATCH API에서의 활용은 아직 이번 복습에서 확인하지 않았다.
- 변수 영역/데이터 영역을 2단계·3단계로 나누는 메모리 그림은 학습용 모델로는 도움이 되지만, 실제 ECMAScript 엔진 구현과 어디까지 동일하게 볼 수 있는지는 추가로 확인할 필요가 있다.
